# 季节地图统一接入与验收规范

主人 2026-11-06 要求：把做茵菲谷、草帽湾时提过的要求整理成一份硬标准，免得做成半成品。
**任何季节地图的新功能，下面每一条都满足才算做完。** 做不到的条目，要在回复里明说缺了什么。
默认原则：**能套用主世界家里现成的动作、效果、流程，就必须套用**，并且和以前的要求保持一致。
**生活精度要完全完全对标主世界**（主人 2026-11-06）。房子里的家具不能另写一套近似的逻辑，
必须走 `prototype/map-test/season_house.js`：它直接跑主世界的 ACTS / EFFECT / lifeArrive / lifeFinish / activityFrame，
所以时长、需求变化、表情和姿势、头顶气泡、日记、心情、做饭到上桌吃饭、中途去厕所，全都和家里一样。
主世界没有的动作（沙发、尤克里里、淋浴、整理衣柜）在那里按主世界的格式补一条，再接进去。

## 0. 新地图怎么接入

新地图沿用主世界的角色、交互和表现。地图提供地形、可走路线和连接口、家具和服务点、NPC 与作息、任务和演出内容。需要新增玩法（如潜水、播种）时，单独实现玩法本身，并接入同一套指令、暂停与存档流程。

| 系统 | 共用行为 | 地图提供 |
| --- | --- | --- |
| 指令与起居 | 已锁定的剧情步骤 → 玩家指令 → 自主照料需求 → 自由活动。点地、方向键、点家具、点任务卡导航都算玩家指令。新指令取消可打断的自主计划，保持玩家路线直到到达、被新指令替换或明确判定不可达。路线结束且距最后一次有效操作至少 20 个现实秒，才允许重新安排自主行为。 | 可走区域、楼梯和出入口、落脚点、家具动作及六种需求的可用地点。 |
| 点击与菜单 | 复用主世界的点击反馈、家具高亮、走到交互点再执行。直接可执行的动作点了就走，有选项的家具和摊位用圆环或现成选择器，按完菜单的那一下不能又点到地面或选中弹出的菜品。 | 点击范围、可用选项、使用位置、朝向及角色遮挡层。 |
| 任务 | 所有任务用同一个任务面板，主线与支线独立折叠，组名不带数量。未接取的主线不显示分组。进行中显示当前目标，点卡片导航，无法抵达时说明原因。完成后可回看记录，旧档保留已接取和已完成状态。 | 稳定任务 ID、归属、接取条件、步骤和目标地点、完成条件、奖励；读档按进度恢复卡片。 |
| 剧情演出 | 先渐暗，在黑场里安排站位、隐藏无关角色并按需换场景，再渐亮开始动作和对白。锁定期间停游戏时间、需求与自主行为，暂停来电和机会卡，只跑演出指定动作。正常结束和读档续演都经同一流程，收尾恢复现场与操控。 | 演员、站位、朝向、出入场路线、台词、表情、分支与环境变化。动作从现有的走、站、坐、转身、待机、表情等能力里选。 |
| 对白与角色 | 用主世界的角色模型和待机动作、主角与 NPC 的原有气泡。任务及特殊对白用白到浅蓝渐变，逐句手动推进。普通闲聊和来电不能盖掉演出对白。 | 固定造型、角色名颜色、按阶段的对白、需要变化的表情。 |
| 存档与转场 | 由游戏的 `snapshot()` / `restore()`、旧档迁移与既有转场入口统一管理。读档能续到正确步骤，重复确认或读档不会重发奖励。 | 稳定的场景与地点 ID、任务进度、需要保留的地图状态和旧位置迁移方式。 |

**玩家看得见的细节也要共用。**

| 在游戏中检查 | 新地图接到哪里 |
| --- | --- |
| 同一扇左右出口用相同的像素箭头、触控范围和目的地提示。走到出口再换区，尽头只显示可走的方向。 | 在 `sceneDirections` 登记目的地和走法，使用公园、茵菲谷和草帽湾共用的导航控件。 |
| 同类 NPC 头顶文字使用同一字号、底色、层级与换行方式。在画面两端、25% 和 50% 缩放下，气泡仍在说话者附近，离场后及时消失。 | 用 `makeNpcPill` 创建、`positionNpcPill` 定位。地图传入扣除相机位移后的头顶坐标。剧情对白另走已有的 `createStorySpeech`。 |
| 点电视或配套沙发用主世界选节目界面，选好再入座。厨房复用选菜、续锅和上桌流程，摊位的价格、余量和不可购买原因就在选项中显示。点击用来打开菜单的那一下不能买东西。 | 季节住宅用 `seasonHouse.furnitureMenu`，店铺用 `FarmUI.shop`，可换装的衣柜抵达后打开 `openWardrobe`。当地菜谱、私人物品与营业时间由地图提供。 |

`tools/check_map_interaction_ui.js` 对正式构建用鼠标验证，对网页版内测可用触屏验证。它覆盖换区、选节目、衣柜、灶台、咖啡座和 NPC 长句。新地图新增类似入口时，把它加入同一套验收。

**任务头标。** 地图判断是否可接取或继续，再调用 `drawQuestMarker(ctx, x, headY, sign, activate)`，传角色或目标的头顶锚点，坐姿和儿童按实际高度传入。`!` 用浅黄底牌表示可接取，`?` 用浅蓝底牌表示当前可继续、交付或追踪。两款都由 `art/src/concept/quest_marker.py` 输出 9×11 像素切角图，共用定位、浮动与减少动态设置。渲染器在前景、天气和光照之后合成头标，转场和模态界面使用同一规则隐藏，画面边缘显示整张底牌，头标避开左右切区按钮。可点击的头标传入任务回调，鼠标直接命中最终画在画面上的底牌。完成后由任务状态撤下标记。用鼠标在 25% 与 50% 检查可见性和位置，并确认标记与任务卡及剧情锁的状态一致。用 `tools/check_quest_markers.js` 核对各地图实际调用及锚点。

**遮挡、轮廓和鼠标命中。** 场景记录实际绘制的透明精灵、世界坐标、落地线和动作。内嵌在背景中的模型由绘图脚本导出遮罩，遮罩扣掉本来就挡住它的前景。运动和翻转使用当前帧及同方向的精灵。从前向后先判实体像素，再判一像素容差。悬停和点击走 `sceneTargetAt()`，描边走 `drawObjectHover()`。地块、出入口方向和探索区域使用各自的区域判定。背景、阴影和发光光晕无独立交互时只参与绘制。镜头移动或裁切后使用 `mapViewport()` 把鼠标和 UI 锚点在屏幕及世界坐标之间互换。验收透明角、细腿、前后模型重叠、镜头移动、25% 和 50% 缩放。详见 [场景遮挡核查](SCENE_OCCLUSION.md)。

**暂停边界。** 一次任务可以跨很长时间。实际执行脚本时（入场、任务指定的走位、对白、表演）持有剧情锁。任务面板里只有一个待办目标、玩家尚在自由探索时，按正常起居运行。玩家从任务卡启程去地点时，按玩家指令保护路线；到场触发脚本后再锁定。已有通话正在进行时，等它结束再开始剧情。夜间作息或红色需求也要遵守指令优先级。

**当前共用入口。** 下列文件在现有构建中有对应实现。新地图从这些入口接入。个别地图的现有分支按下面的验收逐步收拢，共用能力缺哪一项，就在共用层补齐并由接入地图验证。

- [主世界动作与设置](../prototype/demo/index.src.html) 定义 `ACTS`、`EFFECT`、`command()`、`activityFrame()`、`openRing()` 与 `openPicker()`。[季节起居桥接](../prototype/map-test/season_house.js) 直接复用动作和表现，[栗尾市的现有规划判断](../prototype/autumn/game.js) 可作为统一指令优先级的首个验证场景。20 秒门槛目前由栗尾市实现，其他地图按本规范接入时应走共用判断。
- [任务面板](../prototype/map-test/quest_panel.js) 通过 `questBoard.add()` 接收任务列表。现在面板已区分栗尾市故事和支线。如果另一张地图需要自己的主线分组，扩展共用面板的分组登记即可。
- [剧情气泡](../prototype/demo/story_bubbles.js) 已提供 `createStorySpeech()`、`storyLocked()` 与演出锁登记。主世界的动作、时间和社交入口都要遵守同一个锁；[栗尾市剧本与导演](../prototype/autumn/v4/) 是现有的走位、黑场和读档续演参考，其完整演出流程还需抽成共用入口。
- [季节地图构建](../tools/make_season_game_test.py) 同时面向内测和正式构建。正式版只接入已经开放的入口。按目标平台验证，内测成功不能代替正式包或触屏端的验证。

给新地图的基础接入资料列五项：① 场景 ID 和出入口之间的连接；② 路线和可交互点的位置；③ 六种需求分别去哪儿、用什么动作；④ NPC 和任务的 ID、剧本与站位；⑤ 阶段和旧存档的迁移。重绘现有地图时优先保持这些 ID，挪建筑时同步门口、点击区、导航终点和演出站位。气候、天色、灯光和音频按 [场景接入核查](SCENE_INTEGRATION_AUDIT.md) 登记；天气、剧情进度等状态由游戏的对应入口提供。

**在同一构建里对照主世界与新地图实际点测。** 打开小屋的厨房，再打开新地图对应的厨房或摊位，对照高亮、选菜单、走位、姿势、道具与日记。然后做一遍「需求变红 → 点地走远 → 到点 → 等足 20 秒 → 自主照料」，以及「任务分组 → 点卡导航 → 黑场入场 → 对白停留 → 读档续演 → 结算一次 → 恢复操作」。鼠标与已承诺支持的触屏入口各走一遍。优先复用 `tools/check_season_game_test.js`、`tools/check_liwei_v4.js` 和 `tools/check_save_roundtrip.js` 里已有的测试案例；新增规则要通过实际触发流程验证，截图用于检查视觉表现。

## 1. 去留：她不会自己离开
- 在季节地图里，她**绝不自己回主世界**，任何情况下都一样，包括需求变红、没憋住要洗澡、累倒、困了想睡觉、饿了想做饭。
  所有“室内动作”（洗澡、睡觉、做饭、吃饭、上厕所……）都必须被地图自己的房子或旅社接住，
  不能走主世界的“先回家”。
- 唯一例外：草帽湾只有夏、秋两季有航班。她在岛上时秋天结束，就说一句理由（“再不回家就没航班了！”），然后坐飞机回家。
- 离开**只有一个入口**：点小人，在圆环里选「离开茵菲谷 / 离开草帽湾」。离开时播放过场，飞机动画 3 秒。
- 需求照料的顺序：先去地图里的房子（农舍 / 旅社 / 更衣室），没有房子就去地图里最近的设施。
  每张地图都要有能满足**六种需求**的地方。
- 正式版（`--release`）也要测：把需求压到红、膀胱压到 0，确认她留在地图里。

## 2. 房子里的家具：和主世界的家一模一样
家具的标准是“像在自己家里一样”，每件家具都必须做到：
- 点击家具：她走过去 → 用**现成的姿势** → 需求上涨 → 涨满后自动结束，不卡住。
- 姿势要和主世界一致，绝不能让小人凭空消失：
  - 马桶、沙发、长椅、餐椅：坐姿（`pose:'sit'`，用 `iy` 把高度对齐座面）。
  - 床：躺下，盖被子，飘 z。
  - 只有主世界里本来就看不见她的地方，才可以隐藏小人，比如浴缸 / 淋浴。
- 效果要套用主世界现成的：
  - **吃饭**：坐在餐桌前，有咀嚼的动作（表情和 bob 交替），冒小碗气泡，**桌上有那盘冒热气的饭菜**，吃完撤掉。
  - **做饭**：灶台有做饭的动画，做完饭端到餐桌上，她再坐过去吃。
  - **睡觉**：zz。**洗澡**：水花。
- **厨房必须有餐桌和椅子**。
- 鼠标悬停时家具要有高亮，和主世界一样。
- 只能看的东西（画、台灯……）点了以后，她走过去说一句话。

## 3. 自主行动：玩家不操作时她自己的生活
- 玩家一段时间不操作，她要自己找事做。有效玩家指令会立即取消可打断的自主计划，按第 0 条的路线和空闲条件恢复自主活动。
- 可以开始安排自主行为后，任一需求低于 40 时，先照料需求，再考虑自由活动（见第 1 条）。
- 茵菲谷：散步、进屋起居（坐坐、整理、吃东西）、浇水、喂动物 / 摸动物 / 收蛋收奶、偶尔收菜、偶尔摘果。
  **绝不播种，绝不购买。**
- 草帽湾：先去更衣室换泳装，再去海面或水下游泳、坐空着的气垫（过一会儿自己下来）、逛集市、去岸边。
  **绝不摆摊，绝不买卖**；也不去深海远处，那里留给玩家。

- **夜里**（主人 2026-11-06）：和主世界一样 22:30–6:00 在房子里睡觉（夜里起来上厕所可以）；19 点以后多半待在屋里
  （沙发、吃饭、弹琴），草帽湾偶尔夜潜；夜里不去集市。代码：`season_auto.js` night()。
- **社交**（主人 2026-11-06）：社交低了她自己拿手机打电话、发消息、视频（边走边聊，主世界的 remoteSocial），不进屋。
  对话要有这张地图的话题（`season_social.js`；草帽湾：没电脑、晒黑、潜水……；家里养了宠物会想它）。
- **人际**：季节地图里不能邀请朋友 / 爸妈过来，也不能去朋友家、约出门（“太远了”）。爸妈住在茵菲谷：平时早晚在农舍，
  主世界人脉点爸妈「拜访」= 自动去机场飞茵菲谷；春节她在茵菲谷就在农舍过年，主世界春节有的每一步都要有（`season_parents.js`）。

## 4. 圆环和点击
- 她的圆环里只放这张地图能做的事：
  - 草帽湾：冲浪 / 取消冲浪 / 下来游泳 / 离开草帽湾。
  - 茵菲谷：回家 / 回房间歇歇 / 离开茵菲谷。
  - 主世界的「回家」一律替换掉。
- NPC 正在使用某样东西（比如坐在气垫上）时，玩家就不能用它。
- NPC 和任务点不能挡住箭头、家具、动物、树的点击和悬停。

## 5. 对话和任务
- **对话只靠点击推进，绝不自动翻页**。新的一句刚出现的 0.3 秒内，点击不算数。
- 有选项的对话，选项必须看得见；由小人自己说出的那句不显示选项，所以要换成对方来问。
- 任务 NPC 出现的时间要宽松（例如 5–22 时），每天的出现用种子随机，接了任务以后就一直在。
- 每个场景都有随机支线任务；任务文本口语化（`.claude/skills/everyday-dialogue`）。

## 6. 机会卡
- 数量要多，按区域分（海上 / 陆地 / 集市 ……），只在合适的地方抽到。
- **只有少数卡影响丢丢币，其中大部分是加钱**，极少数会扣一点点钱。不能每张都动钱。

## 7. 画面
- 新画的图**先给主人看**，点头后再接进游戏。
- 远景、中景、近景按视差分层滚动，陆地和海上都要分层；远山要低，不能被云挡住，也不能盖住近景。
  远处的薄纱 / 雾不能厚到让画面雾蒙蒙的。
- 海里的生物分布均匀，不扎堆；大型鱼只在更深、更远的地方出现。
- 冲浪、坐气垫等新动作：用现成的姿势加道具，脚面、冲浪板和水面要齐平。

## 7b. UI
- 面板的动效对标 iOS（`season_motion.js` + style.css “iOS motion”）：弹簧曲线打开、淡出关闭、换页只换内容、按下回弹。
  新面板要和草帽湾小摊一样精致；丢丢平板电脑是平板的样子（深色边框、状态栏、App 图标），大小和任务面板一样。

## 8. 做完前的检查清单
1. 用 Playwright 跑新功能，每个新动作、新姿势都**截图亲眼看**：小人在不在，姿势对不对，道具在不在。
2. 第 1 条的去留测试（正式版构建，需求压红）。
3. 第 2 条：这个功能在主世界的家里有哪些动作和效果？逐项对照，缺一项就不算做完。
4. 跑 `tools/check_season_game_test.js`、`tools/check_infei_side.js` 等相关测试。
5. 存档、读档后状态正确。
6. 在 `docs/AGENT_LOG.md` 写一条记录，推送，然后把网页预览链接发给主人。
