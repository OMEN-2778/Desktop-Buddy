# 日常对白润色与文本清单

本轮按玩家确认的范例修改：普通交流围绕具体事情展开，允许简短、客气、停顿和话题中断；减少密集比喻、强行包袱、关系自我解说及总结式感动。不机械地给每句加“哈哈、呀、呗”，保留原版里自然的段子、童趣、梦境和幻想机会卡。

## 本轮范围

- 初识消息、电话、视频各 20 组，以及关系池中的复用副本；九个地点的初识对白去掉反复解释“还不熟”的开场。
- 朋友来访：200 组通用、120 组情境、40 组原有对白；40 种来访理由及接受/拒绝选项；24 个小事件。
- 九个地点的 444 组成人 NPC 主动搭话，保留男女四种称呼分支；96 组儿童对白保留。
- 酒保 100 组、日料摊 62 组及菜品尝味台词；餐厅和影院 24 组、雷雨 42 条反应。
- 来访、餐厅/影院、雷雨共 70 张机会卡的 280 个结果，分别重写情境描述与对应台词；另修订少量公园、酒吧卡片的套话。
- 18 组朋友语音电话整段重写；80 组睡前故事保留题材，润色其中 45 组生硬回复；其余原版话题保留。
- 清洁不足的拒绝搭话、疏远电话等内嵌文案，改成直接且有上下文的表达。

## 数据约束

保留标题、ID、条目顺序、触发条件、男女组合键、说话人 `>` 标记、情绪奖励、友情变化及需求数值。对白可以有不同句数，但不会为润色改动运行机制。不得通过运行时 `replace()` 去“清洗”角色台词，应直接修改来源数据。

当下事实需要符合场景、时间、天气和活动；跨情境的常用台词不要声称主角正坐地铁、正在下雨或刚刚下班。人物情绪要能从事件本身理解，不要求角色解释自己的性格或关系等级。

## 技能来源

- 项目规范：`.claude/skills/everyday-dialogue/SKILL.md`。
- 中文编辑参考：`.claude/skills/humanizer-zh/SKILL.md`，MIT，来源及固定版本见同目录 `UPSTREAM.md`。

技能作为审稿参考；玩家确认的游戏对白风格优先。不采用禁止一切反语、委婉和比喻的规则。

## 清单交付

完整文本总表提供 Excel、CSV、JSON、按来源的 Markdown、可离线搜索的 HTML，以及原始文本源文件与本次修改补丁。机会卡清单含全部 600 张及 2400 个可选结果；正文、选项、结果、台词与效果分别列出。

中文字符串索引覆盖当前 `prototype/demo` 下 45 个文本/逻辑来源文件，包括日记、论坛、自言自语与内嵌界面补充。排除生成的 `index.html`，避免把同一批来源再收录一遍。来源复用副本会重复出现，因此“文本记录数”不等于独立对白组数。JSON 提供数据路径；JS 提供行号及源文件以查上下文；动态模板保留占位符，不虚构最终运行文本。

## 验证

- 比较 JSON 前后结构、说话人标记与全部非文本字段，确认卡片条件、情绪及关系数值不变。
- 比较 JS AST，确认运行代码结构不变；朋友电话仅重写 `lines`，话题和情绪元数据不变。
- 浏览器回归：NPC 搭话四种性别组合、初识/关系池、来电与自主生活、来访和留宿、性格与存档。
- 四档桌面缩放：188 个 UI 状态、600 张卡 × 四档（2400 次排版），以及结果情绪气泡和长文滚动。
