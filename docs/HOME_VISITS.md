# 来访、留宿与测试入口

来访者会在客厅、厨房、书房和卧室间走动；主角换房间时优先过来找主角。浴室保留隐私。闲逛到达后才开始停留计时，不会还在走楼梯就掉头。书房电脑桌右侧的客椅可互动；有人正坐着时保留座位。

父母住在另一座城市。主动邀请通常会被婉拒，提供爸爸、妈妈各十种异地回应。每七个游戏日只重抽一次约 3% 的出行机会，反复点击不重掷；主动探望也有较低概率。成行需要两至四小时，太晚则约次日上午。真实到达时间、行程与抽签结果会保存，婉拒不扣友情。

留宿请求严格限于：成年、非家人、同性、友情值 60–90 的挚友。超过 90 的“最好的朋友”不触发。傍晚来访并待了一段时间后有概率提出；接受后保留客人至次日上午。带头像的独立选择界面停住时间，等待玩家选择，不套用普通机会卡或来访邀请的六秒自动决定。

临睡前安排：

- 你睡沙发：朋友走到沙发，主角睡床。
- 我睡沙发：把床留给朋友，主角的睡觉行动改为走到沙发。
- 一起睡吧：两人实际到达床后，进入枕边闲聊，再入睡。共 80 组，每晚两组，按朋友保存已读历史。聊天期间保持清醒、正常时速；结束后恢复夜间快进和睡眠。主角手动选择睡觉可提前收尾。

三种安排都有对应的卧姿、被褥和真实行走路线。同床时两人的头严格处在同一高度：朋友在后方，仅向左错开 3 个原生像素，不能向上错位；枕头同高并共用被子。沙发上的主角不会因为读档被移回床；夜聊的段落与进度、次晨醒来和告别都可恢复。

网页版下方「临时控制台 → 睡眠画面（测试用）」提供双人同床、主角睡沙发、朋友睡沙发、同床聊天。进入测试时保存正常进度的内存副本；若原本开启自动保存，先保留正常进度到存档。测试画面不写入存档，手动导出仍导出正常进度。退出恢复原有时间、需求、人物、灯光和天气，可以在测试中恢复时间观察后续流程。

文件：

- `prototype/demo/home_visits.js`：状态、亲属出行、留宿选择、卧姿与控制台预览。
- `prototype/demo/home_visit_text.json`：亲属回应、留宿安排、80 组床上闲聊。
- `art/src/concept/visit_furniture.py`：客椅、双人被褥、沙发毯，使用现有调色板。
- `tools/check_overnight_visits.js`：四档弹窗、三条睡眠路线、存档、资格边界、测试存档隔离和公园箭头的实际转场。

公园方向按钮是独立像素 UI，尽头隐藏不可通行的方向。点击沿用现有走路和边缘转场逻辑，不直接改地图。主角晕倒、使用公厕或出现阻塞选择时隐藏。

# 日常对白规范

安装的 [`humanizer`](../.claude/skills/humanizer/SKILL.md) 来自 blader/humanizer，MIT 许可。游戏专用的 [`everyday-dialogue`](../.claude/skills/everyday-dialogue/SKILL.md) 规定中文口语、亲疏程度、时效和角色身份。

电话、消息和普通见面不再固定插入“性格自述”。性格通过完整的小事对话表现，在不同了解阶段使用不同话题。消息短篇、电话/视频故事及关系阶段对白已润色；相同话题在单个池中去重，时效条件仍有效。避免给每段强加温情总结、笑话包袱或机械语气词。

来访期间主角不自主出门：从客人进门到走出家门（entering/visiting/leaving）都禁止自主选出门；已经开始、尚未跨门的自主出门会重新选择室内活动。手动出门保留；客人尚未到家不限制出门；客人真正离开后恢复自主外出。吃饭、洗澡、如厕、睡觉照常。验证见 `tools/check_guest_stay_home.js`。
