## 一、故事规则与角色

主角在阿简敲门前完全不知情，没有联系、举报或干涉任何环节。主角的房屋权利无须靠做任务保住。删除所有树苗、夏日邻居、托付种树情节。

阿简是受程青委托核实旧资产和寻找程铁山的调查者，没有查封、收房或执法权。开场的“收房”来自主角看到材料后的误解，阿简当场解释，不能让他冒充执行人员。

程铁山是仍持有矿场权益的老负责人，退出日常经营却保留旧资产补报权限；故意填入已出售的外地维修站地址，想阻断扩建融资。程青负责实际经营，错误预核查材料在她发现后尚未生效。程序中止与地址更正不等于全部融资危机由主角解决。

三方冲突：程青要保住短期工资与交付，接受有限过渡生产；程铁山要尽快停下所有旧矿生产，接受资产损失；居民要健康、工资和医疗同时有着落，但资金、岗位与时间不够同时满足所有人。没有万能证据、突然出现的大投资人或全员一致拥护。

核心人物只有主角、阿简、程青、程铁山、老郑、苏医生。任务配角以“楼上住户”“维修工”“工人代表”等现有居民身份出现，不扩写新支线关系。

两种结局共有：停止扩建，严重污染的旧炉不再开，旧矿逐步退出，医疗保障继续，少量维修岗位落地。支持决定后续由谁主持；双方事先同意按居民意见选择方案，并由企业办理相应交接，居民没有驱逐权。失去支持者自己决定离开，另一人留下兑现承诺。

## 二、对白与演出通则

每个编号是一段可独立保存的场景。冒号后是实际台词，括号为演出，不出现在对白中。选项下的回复只播放所选一支，随后回到汇合处。所有主线段落必须由玩家主动点击继续，不自动跳字。

- 对方台词：原生上方“对方”行，姓名＋头像。主角台词：自己的对白行。任务/特殊对白白到浅蓝渐变；选择在主角行均分为浅黄色气泡。遵循最新 story_bubbles.js，不恢复头顶大白框或整屏剧情框。
- 现场人物走到谈话点再说话；电话注明“电话”，场外描述用短事件提示，不伪装成NPC发言。多人讨论才安排多人到场。
- 一句最多两小句，长段按下文逐行显示；不把整章塞进一个框。台词不说变量、票数、游戏时间。
- 台词带完整标点（。！？……——～），语气靠标点和短句，不靠旁白解释。主角有自己的吐槽和小反应，不只是提问机。
- 对话、选择、转场暂停需求与世界时钟；正常探索恢复。阿简跟随，不挡路；进入室内一起过门，离开时一起返回。
- 飞机正常进出，无雾霾锁航班；机场→阶梯→机舱完整显示两秒→阶梯→地图。故事不创造天气航空限制。
- 拒绝、收起、回家均不判失败，不丢任务物品。重返后从保存的节点继续。

## 四、触发与状态机（开发接入约定）

### 4.1 主线图
`未触发 → S00 → S01 → S02 → S03 → S04/S05（可交换）→ S06 → S07 → 居民任务＋S08 → S09 → S10 → S11 → S12 → S13 → S14 → S15 → S16A/B → S17 → S18A/B → S19`

T01在S05后可接；T02在T01后可接；T03在S06后可接。三个任务在S09前必须完成，以确保玩家先认识受影响的人。S08只要求留下且完成至少一个任务，可与其余任务穿插。S11不是重复送药修理，而是把前期看到的问题落实为两条路线共同承诺。

S07的房屋正式更正不检查任何T/G任务。S08举报日期固定早于S00。S09一次性污染事件是已有设备问题，不由玩家先做了哪个任务导致。

### 4.2 数据结构
```json
{
  "storyVersion": "maple-house-v1",
  "chapter": "door",
  "node": "S00",
  "line": 0,
  "phase": "idle",
  "flags": {},
  "completedNodes": [],
  "completedTasks": [],
  "evidence": [],
  "inventory": [],
  "concern": null,
```

`flags`使用上文命名。`chapter`只能由提交节点推进，不能靠点击地图或普通聊天递增。道具用唯一ID：`med_bag_T01`、`repair_tools_T02`、`handover_copy_T03`；证据不占可出售背包，不可赠送或销毁。玩家名字运行时替换“我”，不改源文本。

### 4.3 居民支持：透明、确定、不刷好感
支持单位是三组代表意见，不是三个人替全城投法定票。展示“愿意支持／还有顾虑”，具体障碍用居民原话列出，不展示社交好感分。

| 代表组 | 愿意听的前提 | 支持程青方案 | 支持程铁山方案 |
|---|---|---|---|
| H 医疗与受影响住户 | T01 | 医疗到账＋旧炉永久停＋七天上限与异常即停条款 | 医疗到账＋剩余生产立即停止承诺 |
| W 工人家庭 | T02 | 工资底线到账＋欠薪日期公开＋不新增订单 | 工资底线到账＋欠薪日期公开＋真实维修岗位与培训安排 |
| R 维修及小店代表 | T03 | 维修资金/订单确认＋公开岗位培训名单 | 同左，另确认立即停产损失不转嫁工人 |

阈值：至少两组明确支持拟选方案才开放S14确认。为避免送礼买结局，T01/T02/T03和G1/G2/G3都必须完成，之后**仍须主动与至少两组沟通确认**，不自动把完成任务算赞成。按完整主线走，两套方案均有可获得的支持，不设计隐藏不可逆锁死。

这套门槛的作用是让玩家听见代价，而非猜数值；完成所有保障后允许走任一结局。居民的个人保留意见按台词保留，不因代表支持就消失。换意向不重做任务，但需重新确认至少两组针对新方案的意见。相同对话重复不叠票。

### 4.5 工期、资金和环境反馈
- “七天”是故事内书面过渡期限，不是现实七天，也不让挂机玩家错过结局。S17确认后进入收尾时间蒙太奇，事件提示“按约定完成限期过渡”；玩家同意“查看后续”才播放，不推进主世界日历、生日、写信日或基金结算。
- 两路线都先停严重污染旧炉。A只有已通过专业检查的低风险工序可短期运行，限定原料、订单、期限、超标即停；B立即停其余生产。两路线都由专业人员安全停机，玩家不操作工业设备。
- 所有矿场资金是叙事账目，不调用玩家丢丢币，也不设“花币买支持”。已到账与预计收入在证据卡分栏；诊所、生活底线先落实，个人资产需核明权属后处分。不写“一卖仓库全城没事”。
- 阶段0抵达：灰尘明显；阶段1旧炉停：新增排尘减少，旧灰还在；阶段2落实停运：车流减少，街道逐段清理；阶段3后日谈：空气逐渐好转，仍有清理工作。不能让一次站队即刻让病人痊愈、河水全清。
- T02完成可替换台阶/水龙头小状态；T03核对不立刻显示繁忙车间，G3落实后才显示三工位开工。

### 4.6 暂停、存档和幂等
每句看完记`line`；每个选项点击后先存选择再排下一句。节点最后一句确认后原子提交效果：更新flags→写completedNodes→清理pendingEffects。相同node/effect ID最多提交一次，刷新不会重复给道具、支付或离场。

Esc/暂时收起保存到当前未确认句，不自动完成任务。重开继续；可提供“从本段开头重听”，只重播文本不重发效果。任务对话中主角需求冻结；关闭后恢复此前速度，不强制变成1倍。

返家保存地图位置、当前任务与同伴状态；已持药袋/工具保留，阿简不继续在城内替玩家跑任务。返回放在机场安全落点，然后引导去未完成节点，不把玩家载入设备区或过场人物重叠处。

故事界面不能同时与来电、节日、机会卡抢占对白。用统一剧情锁排队；锁释放后按原规则恢复，不重复触发已消费事件。强制过场前玩家已处于危急需求时先满足需求，之后再排队。

旧秋日线性存档：不得把旧quest数字直接映射成新支持/结局。保留外观、家中财产与旧档备份；弹“这是新版故事，是否从门口重新开始”，确认后另建`maple-house-v1`状态。拒绝则保留旧测试档，不静默抹掉进度。

### 4.7 阿简全程陪伴
城外赴约、到达、居民任务、核查、讨论、送行均绑定同伴阿简。寻路跟随保持约20–35原生像素距离；过窄门时依次通过，不推挤主角。闲置时站在任务点旁；不主动选择回家，不代替玩家作最终选择。

过场开始前检查人物到场。附近可走到；远处人物先预约，再切场，不瞬移入镜。电话段落头像显示电话状态。阿简仅有一个实例，不能同时跟随又在广场刷新一位。
